# 搜索可靠性守则

> **这份文档不是"怎么搜得更多"，是"怎么让 AI 不把自己的旧知识当成事实"。**
>
> 内容来自两次真实对照的反推：
> **一次失败**（我拿到了三个来源的一致结论，而那个结论是错的——用户自己的机器就在反例上跑着），
> **一次成功**（同一套守则，同一个结构的问题，先验同样被推翻，但这次答对了）。
>
> 每个机制都标注了**它对应的具体失效**，不是泛泛的建议。
> **并且标明了哪些机制经过验证、哪些没有**——不要把功劳记错。

---

## 零、最根本的一条：AI 的先验什么时候能用

**不是"不要相信先验"，而是"要分清哪些先验会腐烂"。**

| 事实类型 | 例子 | 腐烂速度 | 能否信先验 |
|---|---|---|---|
| 数学 / 物理常数 | 光速、16×16=256 | **永不** | ✅ 可信 |
| 协议 / 语法 / 逻辑 | JSON 语法、SKILL.md 字段、推理规则 | 年 | ✅ 基本可信 |
| **软件能力边界** | 「8GB 内存能不能跑 X」「最低要多少显存」 | **周** | ❌ **绝不可信** |
| **工具 / 版本现状** | 「现在该用什么工具」「哪个方案更好」 | **天** | ❌ 必须现查 |
| **价格 / 额度 / 可用性** | 免费额度、API 价格、是否还在运营 | **小时–天** | ❌ 必须现查 |
| 用户自己的机器状态 | 「我这台跑得动」 | 实时 | ❌ 只能问用户 |

**关键错配**：AI 的训练截止是**年级**；
而「软件能力边界」的变化速度是**周级**（新量化、新蒸馏、新 offload、新引擎）。

> ### 所以这类问题，AI 的先验**必然过时**，而且**它自己感觉不到**。
> 先验不会说"我可能过时了"，它只会让一个过时结论**显得理所当然**。

### 一句话总原则

> **AI 对"世界现在是什么样"没有权威；对"这说不说得通"有权威。**
>
> 凡是「**现在怎么样**」的问题 → 一律现查。
> 凡是「**这逻辑通不通**」的问题 → 可以用先验。

---

## 一、四个阶段 × 九个失效机制

### A. 搜索前

#### A1. 先验没有被显式化 → 它悄悄决定了搜什么、信什么、何时停　⭐ **最高优先级**

**失效**：我心里假设「8GB 内存跑不了大视频模型」。这个假设没有出现在任何地方，
但它决定了我的搜索词、我对 ≥32GB 的接受度、以及我何时停止。

**机制**：先验不是中立的观察者，它是**搜索的导演**。而且它**不可见**——AI 感觉不到自己在用先验。

**对策：先验预注册 + 强制证伪**
1. 动手前**写下一句话预期**：*"我预期 X 不可行 / 我预期答案是 Y"*
2. **专门搜它的否定**：`X 跑通` / `X 成功` / `X works`

把隐式的、不可攻击的先验，变成显式的、可攻击的假设。

> ### 为什么这条排在第一位
>
> **先验不可见，是所有其他失效的源头。** 看不见的先验决定了：
> - 你搜什么词（→ B1）
> - 你信哪些来源、何时停（→ C1）
> - 你把哪个命中判为"无关"（→ B2）
> - 你把阈值读成哪一档（→ C2）
>
> **看不见先验，后面所有机制都只是在事后补救。**
>
> **实证**：在一次对照测试中，唯一让人**当场发现自己结论错了**的机制，
> 就是事先把预期写了下来——否则那个反例只会显得"只是个例外"。

---

#### A2. 约束靠用户提，而不是强制枚举

**失效**：用户这次说了"16 显存 8 内存"，我才想到内存是瓶颈。
**如果他只说"16 显存"，我整条路线都会错。**

**机制**：AI 会围绕**用户提到的**约束优化，不会主动枚举**用户没提到的**约束。
而**瓶颈常常在被忽略的那个维度上**。

**对策：约束强制枚举清单**（不许等用户说）

```
硬件：显存 · 内存 · 磁盘剩余 · 系统(Win/Mac/Linux) · 是否笔记本/散热
软件：已装什么 · 版本 · 是否介意装新的
技能：会用哪些工具 · 会不会写代码 · 愿不愿意折腾
预算：一次性 / 订阅 / 免费
时间：能接受多慢
合规：地域限制 · 商用/非商用
网络：能否访问境外资源
```

> **关键认知：「用户没提」不等于「不是瓶颈」。**
>
> ⚠️ **最常被漏掉、又最常是真正瓶颈的两个维度：`磁盘` 和 `内存`。**
> 实证：一个「核显能不能做本地 AI 视频」的问题，真正的硬门槛是
> **~75GB 空闲 NVMe**（权重要从磁盘流式加载），**既不是显卡也不是内存**。
> **只问"显卡多大"会 100% 找不到答案。**

---

### B. 搜索中

#### B1. 查询表达的是「问题」，不是「解法」

**失效**：我的约束通道查询是 `8G内存 ComfyUI 视频生成 内存不足 爆内存`。
这个查询的语义是「**找关于内存不足的抱怨**」——它**必然**只能捞到抱怨。
换成成功导向的词，立刻捞出一整片我之前没看到的资源。

**机制**：**搜索词里的描述色彩决定了结果空间。**
搜"问题"→ 得到问题清单；搜"成功"→ 得到解法清单。两者**不重叠**。

**对策：每个约束必须发三类查询，缺一不可**

| 类型 | 模板 | 目的 |
|---|---|---|
| **问题式** | `<约束> 报错 / 爆 / 失败` | 知道会踩什么坑 |
| **成功式** ⭐ | `<约束> 跑通 / 成功 / 实测 / 能做到` | 找真正解决的人 |
| **非常规式** ⭐ | `<约束> 技巧 / trick / 极限 / 折腾 / 偏方` | 找越过阈值的配置 |

**第三类最关键，也最容易漏**——因为「怎么用非常规配置越界」从来不写在"要求"章节里，
只写在"极限测试 / 折腾记录 / 避坑"里。

> ⚠️ **诚实记录：本次对照测试中，这条并非决定性机制。**
> 三类查询**都**返回了那个关键反例——也就是说，即使只发问题式查询也能找到。
> 它**有用**（扩大覆盖面、减少遗漏），但**真正拦住错误的是 A1（先验预注册）、
> B2（不丢弃跨域命中）和 C2（阈值分档）**。不要把功劳记错。

---

#### B2. 丢弃了「看起来不相关」的命中（本次最致命）　⭐ **强制条款**

**失效**：我搜到一篇《8 GB GPUs via Hierarchical Offload and **Windows Commit Tuning**》。
因为标题里没有 MMD / MiniMax 字样，我判定为"跨领域无关内容"丢掉了。
**它就是答案**——用户的机制正是 Windows 虚拟内存 / commit limit。

**机制**：**相关性判断是按「领域」做的，而解法往往在领域外。**
内存、速度、精度、并发这类**约束是通用的**，它们的机制和技巧跨领域迁移。

**对策**
- 命中里凡是提到 **机制 / 原理 / 调优 / 论文 / 通用技巧** 的，**不许直接丢弃**
- 若判定为无关，**必须写下理由**；而理由如果是"**领域不同**"——那是
  **跨域借鉴的信号，不是排除信号**
- 每一轮搜索都要专门问一次：*"这个问题在别的领域有没有更成熟的解法？"*

> ### 为什么这条是强制的
>
> **两次失败都栽在这里，而且形式一模一样——按「领域」或「工具名」过滤：**
>
> | 失败 | 我丢掉的东西 | 它实际上是什么 |
> |---|---|---|
> | 第一次 | 《8 GB GPUs via … **Windows Commit Tuning**》 | **答案本身**：Windows 虚拟内存 / commit limit 机制 |
> | 第二次 | 一个「**LTX-2.5** 在核显上流式推理」的仓库 | **答案本身**：它跑的不是我在查的那个模型，但机制完全通用 |
>
> **判据：凡是讲了「机制 / 原理 / 调优」的命中，跨领域、跨模型、跨工具都不能丢。**
> 约束类问题（内存、速度、精度、并发、磁盘）的解法**天生是通用的**。

---

### C. 判读时

#### C1. 把「找到确认」当成「找到答案」

**失效**：三个来源都说 ≥32GB，我就停了。
但那三条**很可能共享同一个流传的二手共识**——它们不是三个独立观测。

**机制**：默认停止规则是「支持证据足够多就停」。
而**来源数量 ≠ 证据强度**：三篇互相引用同一篇的文章，等于**一个**来源。

**对策：改停止条件**
- ❌ 停止条件不是「我找到了支持它的证据」
- ✅ 停止条件是「**我尝试过推翻它，并且失败了**」

**具体动作：每个关键结论必须执行一次「否定查询」**
> 我搜了什么否定查询 → 结果如何 → 结论是否修正

**独立性的判据**：不是数量，是**是否各自有一手实测**。
优先找**带数字、带复现方式、带机器配置**的一手报告。

---

#### C2. 阈值类型混淆：「可行性」被读成「可用性」

**失效**：文档写「内存 ≥32GB **是硬要求**」，我读成"物理不可能低于此"。
它真实的意思是「**≥32GB 才能有可用体验**」。**用户的 8GB + 128GB 虚拟内存在跑。**

**机制**：技术文档里的 `required / minimum / recommended` 携带的是
**体验担保**，不是**可行性边界**。而 AI 会把它们**一律读成硬约束**。

**对策：任何阈值必须拆成两问，并分别报告**

```
可行性阈值：低于它还能不能跑出来？
            （可能要几小时、大虚拟内存、磁盘卸载、极慢）
可用性阈值：低于它还能不能日常干活？
            （社区手册里的 "required" 通常是这个）
```

**且必须主动去找「越过可行性阈值」的非常规配置** —— 它们只在极限测试类内容里。

**输出时两个阈值都要报**，不要说"不可行"，要说
「可用性上不推荐；但如果你愿意忍受 X，可行性的门槛是 Y」。

---

#### C3. 读了「结论段」，跳过「限制段」

**失效**：手册 **§0 结论速览**说「16GB 显存能跑，且适合」，
**§8 避坑清单第 4 条**才说「内存 ≥32GB 是硬要求」。我引用了 §0。
另有一份实测仓库的 `Honest status` 章节明确写了 commit limit 与 pagefile——我也没先读。

**机制**：文档结构里，
**结论段是写给"想快速获得安慰的人"的，限制段是写给"会真正踩坑的人"的。**
而 AI 天然倾向读结论段——它们更短、更肯定、**更像答案**。

**对策：阅读顺序反转**

1. **先读**：`已知限制 / 未验证 / 局限 / 陷阱 / 避坑 / Honest status / Caveats / 不保证什么`
2. **再读**：结论 / 速览 / 推荐配置
3. **可信度映射**：
   - **限制段里的数字 → 当事实看**
   - **结论段里的数字 → 当营销看**
4. 特别留意作者**自己标注为"未验证 / 已推翻 / 撤回"**的段落——**那是最高质量的信息**

---

#### C4. 评价轴偷换：拿你有的证据，回答另一个轴的问题　⭐ **强制条款（新增）**

**失效**：用户判断「LTX / 混元 的输出质量和 MiniMax 天差地别」。
我摆出一张"反证"表说「这两条线在 2026-10 都是活的」——**那是可行性轴的证据，去反驳质量轴的判断。**
**活着 ≠ 好。** 我拿一个我恰好查到过的事实，去回答一个我根本没有证据的问题。

回看我自己找到的材料，**它们全都在可行性那一侧**：
- 那个仓库的 `Honest limits`（运动糊、人脸糊、12fps）→ **是"能跑"的代价，不是质量的证明**
- 作者自述 *"The point is that it runs **at all**"* → **这句本身就承认了它不是质量路线**
- 另一个项目建在**蒸馏**模型上 → 蒸馏为了**快**，不是为了**好**
- 芯片厂商那篇是「AI PC 适配」→ **弱硬件适配 = 可行性工作**

**我一句质量证据都没有，却摆出一张表来"反驳"质量问题。**

**机制**：AI 在某个轴上**恰好有材料**（因为那个轴容易查到），就会**不自觉地把那个轴当成评价标准**，
而**用户关心的往往是另一个轴**。
"我手上有数据"的感觉，会压制"数据不对题"的判断——**所以它感觉很严谨。**

> **这是"自作主张"最隐蔽的形式：它不是无视证据，而是用不对题的证据，冒充对题的论证。**
> AI 用一个**自己有材料的标准**，替换掉了**用户真正关心的标准**，而且**不声明自己换了标准**。

**与 C2 的关系**：**同源**。C2 是单轴内的阈值混淆（可行性 vs 可用性）；
C4 是**跨轴**的偷换（可行性 vs 质量）。两次失败都是"抓着手边的轴，回答另一个轴"。

**对策：评价轴显式化 + 轴匹配检查**

1. **先写下这个问题关心的是哪个轴**（可多选）：
   ```
   质量 · 可行性 · 速度 · 成本 · 稳定性 · 易用性 · 兼容性 · 合规 · 可维护性
   ```
2. **每条证据都标注它落在哪个轴**
3. **轴不匹配的证据不许当论据** —— 注意：不是"丢掉"，而是记为
   「**这个轴我还没有证据**」
4. 轴不匹配时的正确反应只有两个：
   - **去补这个轴的证据**，或
   - **明说"这个轴我没查"**
   **绝不能拿另一个轴的材料去代替。**
5. 输出时**按轴分栏**报，不要把不同轴的结论混在一句话里

---

### D. 收尾时

#### D1. 用资料否定用户的一手观察

**失效**：用户说"我的机器上就是这样的"。
如果我坚持三篇文档，就会**用二手概括否定了唯一的实物证据**。

**机制**：AI 把检索到的文本当作比用户陈述更权威。
但对「**我自己这台机器上发生了什么**」这件事，
**用户拥有最高权威，文档只是他人的概括。**

**对策**
- **用户描述的实际观察 > 任何文档**（尤其他自己的机器、他刚试过的事）
- 矛盾时**以用户为准**，然后**追问细节以搞清机制**
  （这次正是靠追问"虚拟内存多大"，才落实了 commit limit 这个机制）
- 追问要具体到可验证的量：*版本？参数？设置？耗时？报错原文？*
- **绝不说"但是文档上说……"来反驳**，而要说"那和文档说的不一致，可能是什么原因"

## 二、证据分级（按可信度从高到低）

| 级别 | 类型 | 特征 |
|---|---|---|
| **1** | **用户自己机器的实测** | 最高权威，尤其针对他自己的配置 |
| **2** | **带机器配置 + 复现方式 + 原始数字的一手报告** | 有 `results.csv`、脚本、逐位对比的更好 |
| **3** | 官方文档 / 官方仓库 | 权威但**滞后于社区技巧** |
| **4** | 社区实测汇总 / awesome 列表 | 覆盖面好，**要查它的引用是不是同一批来源** |
| **5** | 二手转载 / 教程站 / SEO 内容 | 通常是第 3–4 级的复述，**且会丢掉限制段** |
| **6** | **AI 自己的先验** | **对"当下状态"类问题，这是最低级别，不可单独作为依据** |

> 注：级别 6 不是"永远不可用"——对逻辑、推理、语法、常识，它是级别 1。
> 它只在**「现在怎么样」类问题**上降到最低。

## 三、可直接执行的清单

### 搜索前
- [ ] 写下**一句话预期**（我预期答案是……）
- [ ] 按**约束清单强制枚举**（硬件/软件/技能/预算/时间/合规/网络）
- [ ] 专项搜**预期结论的否定**

### 搜索中
- [ ] 每个约束发**三类**查询：问题式 / **成功式** / **非常规式**
- [ ] 本轮是否有**机制/原理/调优/论文**类命中被我判为无关？**写下理由**
- [ ] 有没有去**别的领域**问同一个问题？

### 判读时
- [ ] **先读限制段**（局限/避坑/未验证/已推翻），再读结论段
- [ ] **写下这个问题关心哪个轴**（质量/可行性/速度/成本/稳定/易用/兼容/合规）
- [ ] **每条证据标注它落在哪个轴**；轴不匹配的**不许当论据**
- [ ] 每个关键结论：**我搜过否定查询吗？**
- [ ] 每个阈值：**可行性**和**可用性**分别是什么？
- [ ] 来源独立性：**它们各自有一手实测吗，还是在互相引用？**

### 输出时
- [ ] 每条结论带**来源 + 日期**
- [ ] **没有来源的结论，明确标注"这是我的推测"**
- [ ] **按轴分栏**报，不把不同轴的结论混在一句话里
- [ ] 阈值分**可行性 / 可用性**两档报
- [ ] 与用户观察冲突时：**以用户为准**，并说明"资料与你的经验不一致，可能的原因是……"
- [ ] 允许说「**没找到**」——不凑数
- [ ] 某个轴**没查**时，直接说"这个轴我没有证据"，**不要用别的轴代替**

## 四、这套守则的一句话版本

> **把"我知道"降级成"我猜"，然后专门去搜"我猜错了会是什么样"。**
>
> **凡是"现在怎么样"的问题，先验一律作废；**
> **凡是"这说不说得通"的问题，先验可以放心用。**
>
> **另加一条（两次失败都是它造成的）：**
> **先问"这个问题关心哪个轴"，再看"我手上的证据在哪个轴"——两轴不一致时，那不是证据。**

## 附二：成功的案例（守则生效）

**问题**：「只有核显的轻薄本（无独显），想做本地 AI 视频」

**先验预注册**：*"核显跑不了 AI 视频。预期答案：不可行，用云。"*

**结果：先验被推翻。** 找到决定性反例——一个普通 Intel 核显 + 15.6GB 共享内存，
靠 **NVMe 逐层流式加载权重**，跑通了**完整未量化的 22B 视频+音频模型**
（5.4s / 1536×896 带音频 ≈ 14 分钟；作者自述 "The point is that it runs *at all*"）。

| 机制 | 触发 | 决定性？ |
|---|---|---|
| **A1 先验预注册** | ✅ | ⭐ **最关键**——写下来了，所以能当场看到它被推翻 |
| **A2 约束强制枚举** | ✅ | ⭐ **决定性**——枚举时列了「磁盘」，而硬门槛正是 **75GB NVMe** |
| **B2 不丢弃跨域命中** | ✅ | ⭐ **决定性**——那个仓库跑的是**另一个模型**，锁死在模型名上就会丢掉 |
| **C2 阈值分档** | ✅ | ⭐ 结论从"不可行"变成"可行但慢；**瓶颈在磁盘不在显卡**" |
| **C3 先读限制段** | ✅ | 拿到真实边界（12fps、人脸糊、CUDA 未测） |
| **C1 反例搜索** | ✅ | 英文否定查询直接命中 |
| **B1 三类查询** | 🔸 | **并非决定性**——问题式查询同样返回了那个反例 |

**7 条相关机制触发 6 条；其中 A1 / A2 / B2 / C2 是决定性的。B1 不是。**
