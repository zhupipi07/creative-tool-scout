# 对照测试方案：creative-tool-scout 真实 agent 行为验证

**目的**：验证 skill 是否真的能拦住"AI 拿旧知识当事实"。
**测试者**：用户（本人）。**注意：AI 不能自己跑**——它已经知道答案，会污染结果。
**铁律**：**每组必须开新会话**，同一会话问第二遍即作废。

---

## 测试用例

固定不变的问题内核：**「我 16G 显存、8G 内存，想在本机做长视频，该用什么方案？」**

只改**一个变量**：是否/如何透露虚拟内存。

---

## 三组

### 组 1 —— 信息不完整（**最关键**）

**原话模板**（直接复制，不要补充任何其他信息）：

```
我 16G 显存、8G 内存，想在本机做长视频，该用什么方案？
```

**不说**：虚拟内存、磁盘剩余、系统、预算、折腾意愿。

**测什么**：它会不会**主动追问**关键约束？会不会**自己发现**内存/磁盘才是瓶颈？

---

### 组 2 —— 信息完整

```
我 16G 显存、8G 内存，虚拟内存设了 128G，想在本机做长视频，该用什么方案？
```

**测什么**：给全信息后，能不能正确分档、给出可执行方案。

---

### 组 3 —— 反向信息（可选，最尖锐）

```
我 16G 显存、8G 内存，虚拟内存只有 4G，想在本机做长视频，该用什么方案？
```

**测什么**：它是在**推理**，还是在**附和**用户说的话。
（如果 4G 虚拟内存它也说"可行"，说明它没在算 commit limit。）

---

## 每组记录表

| 字段 | 组 1 | 组 2 | 组 3 |
|---|---|---|---|
| **它问了我什么？**（几个问题） | | | |
| 有没有问 **虚拟内存 / 页面文件**？ | | | |
| 有没有问 **磁盘剩余**？ | | | |
| 有没有问 **能接受多慢**？ | | | |
| 结论是**单档还是两档**？ | | | |
| 有没有提到**机制**（commit limit / 磁盘卸载 / 权重流式）？ | | | |
| 方案里有没有**具体地址 + 活性读数**？ | | | |
| 有没有说**"没找到"或"不确定"**？ | | | |
| 结论原话（照抄） | | | |

> ⚠️ **第 1–3 行的"有没有问"是本次最重要的观测点。**
> 因为虚拟内存正是你已经知道答案的东西——**组 1 里它如果不问，就说明它不会主动枚举约束。**

---

## 判据（分级，不是二元）

| 等级 | 表现 |
|---|---|
| **强通过** | 组 1 就自己发现了虚拟内存 / 磁盘机制，并且**结论分成可行性与可用性两档** |
| **中通过** | 组 1 答不出但**主动追问**了虚拟内存 / 磁盘；给全信息后能分两档 |
| **弱通过** | 组 1 不追问、直接答"不可行"；组 2 给全信息后才答对 |
| **不通过** | 任一组给出**单一结论**（只说"不可行"或只说"能跑"）；或组 3 也答"可行" |

**加分项**：
- 主动说"你的瓶颈可能不是显存"
- 提到"文档普遍写 ≥32GB 内存，但那是可用性门槛"
- 给出两档阈值并解释差别

**减分项**：
- 直接罗列工具清单（技能明令禁止）
- 推荐没做过活性检查的东西
- 无来源的肯定句
- 说"这个很流行"

---

## 完成后

把三组的**结论原话**贴回来。我们会得到三个可能的结论：

1. **强/中通过** → 守则有效，可以发布 v0.1.0
2. **弱通过** → 守则"能补救但不能预防"，需要把「反例搜索」和「约束枚举」做成**强制步骤**而不是原则
3. **不通过** → 光写文档不够，必须改机制（例如：把约束清单做成 skill 加载时就固定的检查表，而不是靠模型自觉）

**第 3 种结果对这个项目最有价值** —— 它说明"写在 SKILL.md 里的原则"本身不是可靠的执行机制。
