# 实验 03（补测）：评论区抽取 —— 结果是否定性的，并修正了一个说法

**日期**：2026-10-12
**目的**：实验 02 只有 10% 的视频能从简介解析出工具。诊断时看到三条简介写着「链接放在置顶评论」，
于是提出假设：**借物表的一部分内容在评论区**。本实验检验这个假设。
**结论**：**假设被推翻（部分修正）**。

**脚本**：`bili_comments_parallel.py`（并发抓取）、`verify_comments.py`（完整性核查）
**数据**：`data_comments.json`、`data_verify.json`、`data_aid.json`（431 视频，含 aid）

---

## 一、工程发现：评论接口很慢

| 接口 | 单次响应 | 说明 |
|---|---|---|
| `/x/web-interface/view` | ~4 秒 | 正常 |
| `/x/web-interface/archive/related` | ~1 秒 | 正常 |
| **`/x/v2/reply`（无 cookie）** | **~50 秒** | 极慢 |
| **`/x/v2/reply`（带 `buvid3`）** | **~17 秒** | 快 3 倍 |

- `x/v2/reply/main` 接口返回 `-352`（风控），不可用；**`x/v2/reply` 可用，无需登录**。
- 串行抓 180 个视频需 **2.5 小时**（第一次尝试就是这样卡住的）；改为**线程池 8 并发 + buvid3 cookie** 后，
  120 个视频 **10.6 分钟**完成，**0 失败**。
- 置顶评论在 `data.upper.top.content.message`。

---

## 二、主结果：评论没有带来任何新工具

抽样 120 个视频（其中 90 个是刻意挑的"简介有工具关键词但解析不出工具"的**困难样本**）：

| 指标 | 值 |
|---|---|
| 评论抓取成功 | **120 / 120**（0 失败） |
| 简介解析率（抽样内） | 1.7% |
| 简介 + 评论 合并解析率 | **1.7%** |
| **提升** | **+0.0 个百分点** |
| 只有简介能解析出工具 | 2 |
| **只有评论能解析出工具** | **0** ← 关键 |
| 两边都有 | 0 |
| 两边都没有 | 118 |
| 不同工具名：简介 / 评论 | **55 个 / 0 个** |

**这份抽样是刻意偏向困难样本的**（90/120 是"简介里有 MME/渲染/插件/材质/配布 等词，但格式解析不出工具"的），
所以它是对假设的**强检验**：**90 个困难样本，评论区救回来 0 个。**

## 三、完整性核查：会不会是我的提取器太严？

这个疑问是合理的——评论是自由文本，不会用 `MME：xxx` 这种借物表格式。所以做了两层核查。

### (a) 定向核查：实验 02 里三条明确承诺「链接在评论区」的视频

**[BV1EZ4y1L7T6](https://www.bilibili.com/video/BV1EZ4y1L7T6) 【教程】不学建模如何制作MMD模型？（57,974 播放）**

简介原话：「刚发现简介字数上限250，**软件及插件下载链接放在置顶评论中了**」

UP 置顶评论（实抓）：
```
VRoid studio下载：https://vroid.com/en/
VRM转PMX工具下载：https://www.jianshu.com/p/8a4a5993d89f
MMD及PMXeditor下载：https://learnmmd.com/downloads/
Blender下载：https://www.blender.org/
```
→ **承诺兑现了。评论里是四个工具的下载地址。**

**[BV1um421V7So](https://www.bilibili.com/video/BV1um421V7So) 恋活模型转 PMX（52,193 播放）**

简介原话：「**插件包**以及表情参考的pmx模型**打包在评论区**」

UP 置顶评论（实抓）：
```
...插件包在这里链接：https://pan.baidu.com/s/1eZqr3skvfGWPcQhXnkvgeg?pwd=sq5m
```
→ **承诺兑现了。而且是网盘链接。**

**[BV1y2Kr6CEdR](https://www.bilibili.com/video/BV1y2Kr6CEdR) RayToon 渲染配方（5,351 播放）**

简介原话：「借物表见上一个视频」

评论区实抓：只有"感谢开源""想要学习""已收藏"等感言，**没有链接**。
→ 这一条没兑现。

**小结：3 个定向案例中，2 个的评论确实承载了工具的下载地址。**

### (b) 敏感核查：用全局工具词表在评论原文里做朴素子串搜索

这是比格式匹配宽松得多的检验（直接用 45 个已知工具名在评论全文里找子串）：

| 指标 | 值 |
|---|---|
| 成功抓到评论的视频 | 40 |
| **评论里含 URL 的视频** | **9（22.5%）** |
| **评论里命中任一工具名的视频** | **2（5.0%）** |
| 命中的工具名 | `Wind`（1，**疑为英文单词误命中**）、`ikeno`（1） |

**结论：评论里几乎没有工具名（5%，且含误命中），但有相当比例的下载链接（22.5%）。**

## 四、修正的结论

实验 02 的报告里，我写了这样一句：

> ~~「借物表有一部分写在置顶评论里，不在简介里」~~

**这句话不准确，现修正为：**

> ### 评论区承载的是「**下载地址**」，不是「**工具名**」。
>
> | 信息类型 | 主要位置 | 评论区覆盖率 |
> |---|---|---|
> | **工具名**（借物表） | **简介** | ~5%（含误命中），实质≈0 |
> | **下载地址** | 简介 + 评论 | **22.5%** |
> | 视频互链（b23.tv） | 评论 | 常见 |

- **发现工具** → 只需要简介。
- **找到下载** → 简介和评论都要抓（但链接会失效）。
- 评论里只有链接没有工具名，是**社区惯例**决定的，不是解析器的问题。

## 五、意外发现：评论区是「排错知识」的来源

在 BV1EZ4y1L7T6 的评论区里抓到一条高质量内容：

> 「笔记：在 Blender 导入 PMX 模型后渲染时若出现**模型泛紫**的情况，应将所有材质的
> `MMDShaderDev` 中的 **Toon Tex Fac / 卡通纹理系数改成 0**。此设置适用于在 Blender 运行渲染。」

**这是「具体报错 → 具体解法」的知识，出现在评论而不是简介。**

这条线索值得单独记一笔，因为它直击用户最初的诉求：

> 新手的原话是「模型导入后无法显示」「看一晚上教学，眼睛会了手不会」
> —— **他们卡在报错上，而报错解法大量存在于评论区的问答里。**

**所以评论区的价值不在"发现工具"，而在"排错"。** 这是一条与工具发现**并行**的需求线，之前几轮讨论里我们没把它当成一个独立的数据源。

## 六、局限

1. **只抓了评论第 1 页**（20 条 + 置顶）。翻页可能还有内容，未验证。
2. **抽样偏向困难样本**（90/120），所以"简介解析率 1.7%"低于全样本的 10.0%，这是设计使然，不是矛盾。
3. **"Wind" 是误命中**：`is_tool` 过滤无法区分英文工具名与普通英文单词。
4. **未测翻页增益**，也未测"评论区问答"的规模（只观察到 1 例）。
5. 单次实验，未做重复测量。

---

## 七、对产品设计的影响

1. **解析率的瓶颈在「格式多样性」，不在「数据源缺失」。**
   简介可解析率 10%，而 61.7% 的视频有结构化借物表字段 —— 差距全在解析规则上。
   **改进方向是解析器，不是抓更多来源。**

2. **工具发现只需要简介；下载地址需要简介 + 评论。** 两者要分开处理，不要混成一个抽取任务。

3. **"排错知识"是一条被忽略的独立数据源。**
   评论区（以及贴吧/CSDN）里的「报错→解法」问答，直接对应新手最强的痛点。
   建议在 v0 之后单独做一条线。

4. **工程结论**：抓评论必须并发 + 带 cookie，否则 50 秒/次的延迟会让任何批量任务不可用。

---

## 八、下一步

1. **优化解析器**（这是提升解析率的唯一有效手段）：
   - 攻 `效果名（类型）：作者` 格式
   - 处理 `MME xxx/yyy`（无冒号）
   - 处理借物表跨行、含括号说明的情况
2. **测「排错知识」的规模**：抽样搜「模型导入后无法显示」「MMD 卡顿」等报错词，看解答在简介/评论/贴吧的分布。
3. 若要提升评论收益，需实测**翻页**（第 2-5 页）是否有增量。
