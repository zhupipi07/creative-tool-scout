# 实验 02：B站借物表挖掘 —— 工具名的真实可见性

**日期**：2026-10-12
**目的**：验证实验 01 遗留的两个问题——
(1) "好用但只有几百播放"是否真实存在（实验 01 只能用星标数当替代证据）；
(2) 好工具的名字出现在**标题**、**标签**、还是**简介**里（决定搜索该打哪个字段）。
**方法**：从 B 站公开接口爬取 412 个 MMD 相关视频，解析简介中的「借物表」，统计工具名分布与可见性。

**脚本**：`bili_credits_crawl.py`（抓取）、`analyze.py` / `analyze2.py`（分析）
**数据**：`data_mmd_raw.json`（412 条原始记录）、`data_mmd.json`、`analysis2.txt`

## 二、决定性指标：工具名的可见性

### 修正前后两个版本，结论一致

| 口径 | 不同工具名总数 | 出现在过标题里 | **只出现在简介/借物表里** |
|---|---|---|---|
| 宽松（含作者名） | 95 | 2 | **93（97.9%）** |
| 修正（仅英文效果名） | 57 | 1 | **56（98.2%）** |

唯一"出现在标题里"的那个是 **`MMD`** 本身——它是领域名，不是工具名。

> ## 结论：MMD 生态的工具名，**约 100% 只存在于作品简介的借物表里，从不出现在标题里。**

**这个结论的直接后果**：
- B 站搜索、搜索引擎、以及一切**以标题为主要字段**的关键词挖掘，**结构性地看不见这些工具**。
- 实验 01 里"挖词"能生效，是因为它挖的是**标题里的领域黑话**（MME / PMX / 卡渲）；而**具体的工具名，标题里根本不存在**。
- 所以工具发现必须走**借物表通道**，这是一个独立的、此前没被利用的数据源。

### 两个推论

**推论 1（需求验证）**：在整个 412 视频样本里，**收藏/播放比最高的内容，前三名全是"工具在哪找"**。
283.5 收藏/千播 意味着**每 1000 个观众有 283 个收藏了它**——这是"我以后要用"的行为。
→ **用户找不到工具，而且是反复找不到。** 这是从真实行为数据里长出来的需求证据。

**推论 2（长尾实证）**：`VMD Sizing` 是一个开源免费的 VMD 骨架适配工具，**4,080 播放、1,105 收藏（27% 收藏率）**。
→ **实验 01 无法验证的"几百播放但好东西"假设，本次用播放量直接证实。**

## 五、借物表的三种格式（供解析器设计）

从样本里学到的真实格式：

```
格式1  效果名（效果类型）：作者          ← 信息量最大
       ikClut_RC（滤镜）：RedialC/iKeno
       msUnsharp（锐化效果）：ましまし
       MotionBlur3（运动模糊）：そぼろ
       → 工具名 + 用途 + 作者，三者齐全

格式2  MME：名字/名字/名字               ← 工具与作者混在一起
       MME：P.I.P/HAToon2/ExcellentShadow/化身バレッタ/角砂糖

格式3  MME 名字 名字（空格分隔，无冒号）  ← 最弱，切分靠猜
       MME びーと/less./Caeru/鍵束/P.I.P
```

**格式 1 是理想目标**：它自带"这个工具是干什么的"（滤镜 / 锐化 / 运动模糊）——这正是我们想要的"用途标注"。

## 六、发现的解析缺陷（诚实记录）

本次只有 **52 / 412 = 12.6%** 的视频能解析出工具名。诊断后确认原因：

1. **格式太多样**，规则覆盖不全（见上）。
2. ~~**借物表有一部分写在置顶评论里，不在简介里**。~~ **← 此推测已被实验 03 推翻，见下。**
   样本中的原话：
   - 「刚发现简介字数上限250，**软件及插件下载链接放在置顶评论中**了」
   - 「插件包以及表情参考的pmx模型**打包在评论区**」
   - 「借物表见上一个视频，这个视频简介字数有限」

   > **实验 03 的修正结论**：评论区承载的是「**下载地址**」，不是「**工具名**」。
   > 定向核查 3 个承诺"链接在评论区"的视频，其中 2 个的评论里确实有工具的下载地址（成立）；
   > 但用 45 个已知工具名在 40 个视频的评论原文里做朴素子串搜索，**命中率仅 5%（且含误命中）**。
   > 所以：**发现工具只需简介；找下载地址才需要简介+评论。**
3. **作者名与工具名混淆**（v1 的问题，v2 已分离）：`そぼろ / ikeno / Rui` 是**作者**，`ikClut_RC / msUnsharp / MotionBlur3` 才是**工具**。

**所以 12.6% 是解析器的不足，不是借物表文化的覆盖率不足。** 61.7% 的视频有结构化借物表字段，说明这个数据源本身是充足的。

## 七、本次实验的局限（诚实声明）

1. **采样偏差**：样本是从 10 个**热门种子**经 `related` 扩展来的，**长尾被系统性低估**。真实的长尾比例（<1万播放）应远高于本样本的 13.1%。
2. **播放量分布不可外推**：本样本 p25=21,734 / 中位=82,255，是从热门视频扩散的圈层，不代表 MMD 全站分布。
3. **解析率低**（12.6%），工具清单是不完整抽样。
4. **未做重复测量**，单次实验。
5. 播放量分布分桶：

| 分桶 | 数量 | 占比 |
|---|---|---|
| < 1千 | 2 | 0.5% |
| 1千 - 1万 | 52 | 12.6% |
| 1万 - 10万 | 167 | 40.5% |
| 10万 - 100万 | 137 | 33.2% |
| >= 100万 | 54 | 13.1% |

## 八、对产品设计的直接影响

1. **工具发现必须走"借物表通道"，不能只搜标题。**
   工具名 ≈100% 不在标题里。这是一条**独立于关键词搜索**的发现路径，而且社区已经免费替我们维护好了标注。

2. **"从作品反推工具"被证实可行且可自动化。**
   每个作品简介就是一份工具清单。而且**作品比工具更容易被发现**（作品有传播，工具没有）。

3. **需求已被行为数据验证。**
   样本里收藏率最高的内容就是"工具在哪找 / 工具推荐"。**这个产品要解决的是真实存在且被反复表达的需求。**

4. **提取范围必须包含评论区**，不能只看简介（简介有 250 字上限）。

5. **解析器要按三级格式分层设计**，优先攻格式 1（它自带用途标注）；格式 3 需要更多样本才能提高切分准确率。

## 九、下一步实验

1. **加评论区抽取**：`/x/v2/reply` 接口，把置顶评论纳入解析范围，预计解析率可从 12.6% 显著提升。
2. **按「通道」对比命中质量**：标题通道 / 标签通道 / 简介通道 / 评论区通道，量化各自能捞到多少工具名。
3. **测网盘链接失效率**：抽样若干历史视频里的网盘链接，测实际失效率——这能量化"静态清单的半衰期"。
4. **扩样本降低偏差**：用标签页（`/x/tag/archive`）而非相关推荐扩展，长尾比例会更真实。
