# creative-tool-scout

**一个给 AI 用的「找工具」技能。** 覆盖 AI 生成（生图 / 视频 / 3D / 音频）与传统创作（绘画 / 建模 / 动画 / 剪辑 / 音乐 / 摄影）多个领域。

我让 AI 帮我找一个工具，它给我的全是三年前就死掉的东西，还有一堆我用不上的。
后来我发现问题不在 AI，在于**它不知道该怎么搜这个社区**。

---

## 它解决什么

用户给出需求（"我想做一段 XXX"），AI 去找当下真正能解决它的工具。通用 AI 搜索做不好这件事，原因有四个，都是结构性的：

| 失效 | 机制 | 解法 |
|---|---|---|
| **排序失效** | 搜索引擎按流量/SEO 排，不按质量排 | 用**来源优先级表**替代"搜全网" |
| **词汇失效** ⭐ | AI 不知道领域黑话，搜「怎么让角色动起来」而不是「VMD 骨骼 retarget」 | **先把需求翻译成领域术语** |
| **时效失效** | 训练数据过期 + 网页无日期，会推荐已死的工具 | **运行时活性检查** |
| **收敛失效** | 好选项太多 → 模型推荐"被提到最多的"而非"最适合你的" | **结合用户约束筛选** |

**词汇失效最致命，也最好治。** AI 用错词搜，就永远搜不到对的东西，而且它不会告诉你"我搜错了"。

---

## 核心方法：找该领域的「天然工具清单」

这是它区别于普通搜索的地方。

> **每个创作领域，创作者都会因为署名习惯、合规要求或协作需要，在发布作品时留下工具标注。**
> **找到这个副产品，就找到了该领域最真实的工具清单——而且是社区免费、持续维护的。**

`references/byproduct-map.md` 里有完整地图，例如：

| 领域 | 天然工具清单在哪 |
|---|---|
| MMD / 3D 动画 | 作品简介的**借物表** |
| AI 生图 / 视频 | **图片内嵌元数据**（模型与 LoRA 的 hash）、Civitai 作品页 |
| 摄影 | **EXIF** |
| 音乐制作 | 采访/拆解内容里的 VST 插件与设备清单 |
| 软件 / 插件 | 依赖清单 |

**为什么不能靠预存清单**：这些渠道**网盘出现次数超过 GitHub**，而网盘链接会失效；同时新工具出现极快。

### 一个实测证据

我抓了 412 个 B 站 MMD 视频，提取 57 个工具名，逐个检查是否出现在标题里：

| 口径 | 不同工具名 | 出现在过标题里 | **只在简介/借物表里** |
|---|---|---|---|
| 仅英文效果名 | 57 | 1 | **56（98.2%）** |

唯一"出现在标题里"的那个是 `MMD` 本身——它是领域名，不是工具名。

**所以：以标题为主要字段的搜索，结构性地看不见这些工具。** 这是"天然工具清单"方法存在的理由。

而且工具的生命周期很紧：有个正好解决"新手+不懂美术"需求的插件创建于 **2026-09-17**——
**任何在那之前写好的静态清单，在物理上不可能包含它。**

## 它做什么

1. **需求澄清**——最多问 2 个问题（目标 + 硬约束）。**不问"你想用什么工具"**（他不知道才来找你）
2. **翻译成领域黑话**——没有该领域词表时，先做「领域侦测」现场生成一份
3. **四通道并行搜索**——黑话 / 约束 / 痛点 / **溯源**（实测四通道结果文档级零重叠）
4. **挖天然工具清单**——从作品反查工具（作品有传播，工具没有）
5. **活性检查**——现查是否还活着，绝不推荐死掉的东西
6. **输出 1 条主路径 + 2 条备选**，标明"你已有的不用装""活性读数""已知坑"

**它不给你"10 个神器"。它替你砍掉 99 个选项。**

## 结构

```
creative-tool-scout/
├── SKILL.md                       # 通用流程（领域无关，几乎不会过时）
├── references/
│   ├── byproduct-map.md           # 跨领域：各领域"天然工具清单"在哪 ← 核心依据
│   ├── mmd.md                     # 领域包：MMD（已验证）
│   └── _template.md               # 新领域模板
└── experiments/                   # 验证结论的实验与原始数据
```

**流程在 `SKILL.md`，知识在 `references/`。**

加新领域：复制 `_template.md` → 填 → 存为 `references/<领域>.md`。**不需要改 SKILL.md。**

**没有知识包也能用**：SKILL.md 的「领域侦测」会在运行时现场生成一份最小知识包（采黑话、定位天然工具清单、定来源），
用过的领域再落盘成正式领域包。所以它第一天就能覆盖任意领域，并随使用变厚。

## 它做不到什么（诚实说明）

- **目前只有 MMD 一个领域包是经过实测的。** `byproduct-map.md` 里其他领域标了 `[已验证]` / `[常识]` / `[待验证]`，请注意区分。
- **工具名提取的解析率约 10%。** 61.7% 的作品有结构化借物表字段，但格式太杂。**瓶颈在解析规则，不在数据源。**
- **评论区几乎没有工具名**（实测 0/120）。评论区的价值是**下载地址**（22.5%）和**排错知识**。
- **不安装任何东西。** 本技能只做侦察和推荐，不会往你电脑上装软件。

## 想要什么反馈（v0.1.0 beta）

### ⭐ 最有价值的一种反馈：A/B 对照

**同一句话，问两次**——
① 装了本技能；② 把技能移走（从 `~/.dsh/skills/` 移出去），或用另一个没装的 AI。
然后把**两个答案都贴出来**。

**为什么这个最有价值：我们自己已经测过一轮，结果是"平手"。**
拿「16G 显存 8G 内存想本地做长视频」这个问题，装与不装**都答对了**（都指向 MiniMax H3）。

我们的猜测是：

> ### 一个话题越热门，本技能越没用；越长尾，本技能越有用。

理由：热门话题的资料满街都是，普通 AI 也能答对；而冷门、新出现、或约束刁钻的问题，
才需要 `byproduct-map.md` 那套方法（找署名副产品、找约束专门化配置包、跨领域借机制）。

**所以请特别告诉我：**

- **在什么问题上，它和普通 AI 没有区别？** ← 这比夸它有用有价值得多
- **在什么问题上，它找到了普通 AI 找不到的东西？**
- 它**淘汰**某些方案时，给的是**理由**（带来源和日期）还是**热度**（"这个最主流"）？
  如果是后者，那它**违背了自己的核心原则 2**（热门 ≠ 适合），请直接指出来。

### 其他想问的

**1. 在你的领域，工具名到底藏在哪？**
我做 MMD 时发现工具名 ≈100% 只在作品简介的借物表里，不在标题。
`references/byproduct-map.md` 里我对其他领域做了推测（AI 生图 → 图片元数据；摄影 → EXIF；音乐 → 采访里的插件清单）。
**这些推测对不对？有没有我漏掉的"天然工具清单"？**

**2. 哪个领域的知识包最该先做？**
目前只有 `mmd.md` 是实测过的。其余领域要靠「领域侦测」现场生成。
你希望下一个补哪个？

**3. 报错和排错该不该单独做一条线？**
我做实验时发现：**"找工具"是低频需求，"排错"是高频需求**，
而且大量报错解法存在于评论区问答里（例如"Blender 导入 PMX 后渲染泛紫 → 把 MMDShaderDev 的 Toon Tex Fac 改成 0"）。
要不要把"排错"做成独立能力？

**4. 你的领域里，有没有"内容被平台过滤"的坑？**
实测发现 MMD 创作者分享网盘链接时会写"防删版"（在域名中间插字）。
其他平台还有什么类似的规避写法？这直接影响抓取成功率。

**5. 你被它误导过吗？**
最需要警惕的是：它**信心十足地给了一个过时的答案**。
如果发生，请把当时的原话和后来发现的真相都贴出来——**那是最有价值的 bug 报告**。

> 欢迎在 Issues / Discussions 里贴**具体的失败案例**（你问了什么、它给了什么、你觉得应该是什么）。
> **「它和普通 AI 没区别」是最有用的反馈。**
